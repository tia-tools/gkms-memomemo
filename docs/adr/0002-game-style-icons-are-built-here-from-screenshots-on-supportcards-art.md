# Game-style skill card icons are built here from the player's screenshots, on art from gakumas-supportcards

This replaces ADR 0001 and keeps its data half unchanged: the skill card data file comes from gakumas-supportcards at runtime (its `/data/skillcards.v1.json`, proxied by this app's Worker, D22), and so do the card art masters, every P-idol's variant, which supportcards' image pipeline extracts from the game into the shared R2 bucket `tia-assets` and its own local library. What changes is the icon the page draws. The page now draws each card as the game draws it: frame by rarity and type, values, badges, ＋ and A/M over the chosen idol's art. The game's drawing of a card exists only on screen, so the pipeline that makes these icons runs in this repository, from screenshots of the game's P図鑑 that the user takes. It identifies each card by matching its art against supportcards' masters, lifts the game's overlay off the art, and paints it onto every idol's art. The result is sprite sheets per plan and idol, with a cell per card level, and the H.I.F. ability icon uses the base card's cell. They are uploaded from the user's machine under this app's own prefix `gkms-memomemo/` in `tia-assets`, which this app's Worker serves; the index naming the cells is committed here and ships with the page. supportcards' own sprite sheets are no longer read by this app.

The alternatives were these. The pipeline could live in supportcards, but the screenshots are taken by hand and have no place in its daily job. The overlay could be laid over supportcards' sheets in the page with CSS: that is smaller, but places the art under the frame at fractional pixels in the browser, risking a seam at the window's edge, and ties the page to another repository's sheet layout. The sheets could be committed here instead of uploaded: that is free to serve, but adds about 12 MB of binaries to git history per full build. The cost of this choice is write access to the shared bucket from this repository, kept to the one prefix, and a manual step whenever the game adds a card or changes one. The page draws a placeholder (the blank frame of the card's rarity and type, with its name) until the user takes the screenshot. A daily check opens an issue and posts to Discord through nudge when a card needs one.
